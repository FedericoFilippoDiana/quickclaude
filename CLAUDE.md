# QuickClaude

A Spotlight-style macOS launcher for Claude Code: ⌥Space opens a floating panel, a typed prompt gets a streamed answer, and ⌘↩ turns it into a chat. It runs the user's own Claude Code (subscription login, their CLAUDE.md, settings, MCP servers, skills) through the Claude Agent SDK. No API key.

The app lives in `quickclaude/`; run every command below from there.

## Deploy

When asked to deploy, run `./deploy.sh`. It builds the release app, stops any running copy (installed or `tauri dev`), installs `/Applications/QuickClaude.app`, adds a login item (`--no-login` skips it) and launches it. Report its final line, and check that only one copy is running afterwards: two copies fight over ⌥Space.

## Commands

- `npm run tauri dev`: dev build; runs `sidecar/agent.mjs` with node and hot-reloads the UI.
- `npm run tauri build -- --bundles app`: release build only, no install.
- `npm run build:agent`: compile the sidecar to `src-tauri/binaries/` with bun (runs automatically before dev and build).
- `npx tsc --noEmit -p .`: typecheck the UI.

## Layout

- `src-tauri/src/lib.rs`: Rust shell. Panel window, global hotkey, menu bar icon, hide on blur, spawns the sidecar and relays JSON lines between it and the UI (`agent_send` command, `agent` event). Restarts the sidecar if it dies.
- `sidecar/agent.mjs`: Agent SDK host. Keeps one Claude Code process pre-started with `startup()` so a new question skips start-up; follow-ups are pushed into the live session's input stream. Stdio protocol is documented at the top of the file.
- `src/App.tsx`, `src/App.css`: SolidJS UI. Compact view hugs its content; chat view is a fixed 640px panel. Markdown goes through DOMPurify.
- `deploy.sh`: build and install.

## Behaviour to preserve

- **Full Claude Code by default** (`QUICKCLAUDE_PROFILE=full`): `settingSources` user/project/local, the `claude_code` system prompt and tool presets, cwd `~/QuickClaude` (`QUICKCLAUDE_DIR`; history, resume, delete and ⌘⇧H all use it, so ~'s chats stay out), and `bypassPermissions` to match the user's terminal. `lean` is a tool-less fast mode kept for comparison.
- **Subscription only**: the sidecar and the Rust shell both strip `ANTHROPIC_API_KEY`.
- **Uses the installed `claude`** (`pathToClaudeCodeExecutable`), not the SDK's bundled 248 MB copy, so the app tracks the terminal's version. The packaged app has no fallback copy.
- **Login-shell PATH**: apps launched from Finder or at login get a bare PATH, so the sidecar copies the PATH from `zsh -ilc` at start-up. Find executables by scanning PATH directories, not by calling `which` (it missed the updated PATH in the compiled binary).
- **Dragging**: any spot that isn't a control or selectable text drags the panel (`startDragging`). The first show centres it; after that it reopens where it was left, dragged or not (the shell's `Placed` flag), until restart or ⌘N. A fresh panel (only an empty input: no answer, chat, screen, draft or images; the UI reports it with `set_fresh`) always reopens centred, unless full screen.
- **Dropped files**: dropping files on the panel inserts their full paths at the cursor (Tauri's `onDragDropEvent`; the DOM never sees the paths).
- **Reopen behaviour**: hiding keeps the full state while the app runs: answer (finished or not), chat, open screen (history, preferences, shortcuts), draft, cursor and scroll. Reopening history refreshes the list and disarms a pending delete. Nothing is saved across restarts.
- **Keys**: ↩ new question (fresh session), ⌘↩ follow-up and switch to chat, ⇧↩ new line, ⌘. stop, ⌘N new chat (from any screen, history, preferences and shortcuts included; the panel glides back to the centre with `center_panel`, except in full screen), ⌘, preferences, ⌘/ keyboard shortcuts (an overlay in the Preferences layout, listing every key from `KEY_SECTIONS`; by default the panel shows no key hints; the ⌘, "Show shortcut hints" pref (off by default) adds a faint, clickable legend under a new, empty chat (`HINTS` in App.tsx). Keep both lists in step with any key change), ⌘T keep on top (the panel stays up when another app takes focus; ⌥Space then just refocuses it; not saved; a clear accent ring with a soft inner glow marks it, and toggling turns the spark a quarter and says "Keep on top: on/off" in the placeholder), ⌘F full screen in any view (fills the screen's work area with a centred ~1040px column; the shell's `Full` state skips recentring and puts the panel back where it was; not a native full-screen Space; not saved; dragging is off while full), ⌘⇧H continue in a terminal (a native app-menu item in place of the default Hide items; the shell emits `to-terminal`. Not ⌘H: the user's AeroSpace swallows it system-wide): a new herdr workspace (`herdr workspace create` + `herdr pane run`) when herdr is running, else Ghostty, else Terminal.app. Tab cycles the model and ⇧Tab the effort (the label highlights the changed half, shows dots for the model's place, and the empty placeholder names the new choice). On an empty input, ↓ opens history; there ⇧↑↓, ⇧click, ⌘click and ⌘A select several chats (Esc drops the selection first), and ⌫ (on an empty search, or ⌘⌫ / forward delete) marks them and a second press deletes them from Claude Code (`deleteSession`). ⌘P pins or unpins the row under the cursor (or the selected ones; if all are already pinned it unpins them). Pinned chats head the list, newest pin first, with a small accent pin; the rows slide to their new places (FLIP with `el.animate`, the pinned row lifted on `--panel-solid`), the cursor follows the chat, and its time briefly reads "Pinned" / "Unpinned". Pins persist in `~/Library/Application Support/QuickClaude/pins.json` (id → pinned-at, written by the sidecar; deleting a chat drops its pin), and the sidecar sorts pins first before its 300-row cap so old pinned chats never fall off. Esc, Tab, ⌘⇧H, ⌘N, ⌘T and ⌘. (and ⌘F, ⌘/, ⌘, everywhere) also work when focus has left the input (e.g. after selecting chat text). Esc steps back: close the list, cancel an asked compact, then clear the input, then close the chat back to an empty input (if it is still working it keeps running in the background), then hide. ⇧Esc just hides, from any screen, changing nothing, so the panel reopens exactly as it was.
- **Background work survives**: a chat counts as working while a turn runs, while Claude Code reports live background tasks (`background_tasks_changed`, non-ambient), and for up to 15 s after one ends (Claude Code then replies by itself). Leaving a working chat (Esc, ⌘N, a new question, opening another chat) parks its process instead of closing it; it closes once idle. Reopening a parked chat reuses that process. A reply that arrives on its own triggers a macOS notification unless that chat is on screen; clicking it opens the chat. Working chats get a green lamp in history. Esc on an expanded chat always goes back to an empty input (a working chat keeps running parked); ⌘⇧H is blocked while working (moving would kill the tasks).
- **Context gauge**: after every turn, on reopening a chat and after a compact, the sidecar sends the chat's context size from `getContextUsage` (`summary`, the same total as `/context`). From 100k tokens a small amber pill shows it at the right of the chat's title bar, red from 200k (`CONTEXT_WARN`, `CONTEXT_HIGH`); Hidden below 100k, so short chats show nothing. Clicking it asks first: the pill opens out to "Compact 398k?" (a grid-column transition, no key for it; ⌘K was removed on purpose) and a second click sends `/compact` into the same session; Esc, typing, another chat or 5 s cancel. The chat stays on screen with a "Compacted: before → after tokens" note, the after measured with a full `getContextUsage` count since `post_tokens` covers only the messages. Blocked while working; no away alert; reopening a chat mid-compact says "Compacting…"; a reopened compacted chat starts with an "Earlier messages were compacted" note, since Claude Code returns only the post-compact transcript.
- **Away alerts**: whenever a chat fully finishes (no background work left) the sidecar emits `notify`; the Rust shell ignores it if that chat is on screen, otherwise it follows the ⌘, preferences (`~/Library/Application Support/QuickClaude/settings.json`): play `src-tauri/sounds/reply.mp3` (Pixabay "New Notification 3", bundled as a resource, played with `afplay`), bring the panel forward with that chat (only if the panel is hidden, so it never pulls you out of another chat), or show a notification (skipped when it comes forward). ⌘, or the menu bar's "Preferences…" opens the settings screen. Its Theme row (System / Light / Dark) makes the shell set the window's appearance (`set_theme`); the CSS follows it via `prefers-color-scheme`, so colours live in `:root` tokens with a light override. Its Accent colour row (clay, the default, blue, green, teal, purple, pink) sets `data-accent` on `<html>`; each colour overrides `--accent` (a darker shade in light mode) and `--accent-rgb` (for translucent tints), so never hard-code the orange.
- **Chat scrolling**: opening a chat or changing view jumps to the end. While a reply streams, the ⌘, "While Claude writes" pref (`chatScroll`, default `follow`) decides: `follow` follows the reply only until your question reaches the top, then stays put; `stay` never moves by itself (your question stays where it was, at the bottom); `top` puts your question at the top at once, padding the list's bottom (`fitRoom`) so there's room for the reply, the padding shrinking as it grows so nothing moves. Scrolling yourself stops any following. A round ↓ button at the bottom of the chat appears whenever there's more below (accent and pulsing while the reply is still being written) and scrolls to the end.
- **Usage bar**: a 1.5px line on the panel's bottom edge, filled to the share of the 5-hour plan limit used (amber past 80%, red past 95%), refilled on every show. The sidecar reads it with the SDK's experimental `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` (cached 30 s); hidden if unavailable. Clipped to the rounded corners with `clip-path` (WebKit ignores rounded overflow for the transformed fill). Toggle in ⌘, (on by default).
- **Motion, kept clean**: every show and hide goes through the shell's `show_panel` / `hide_panel` (the UI calls the `hide` command, never `win.hide()`), which fade the whole window with AppKit's animator (`setAlphaValue`, 0.18 s in, 0.12 s out; blur and shadow fade too); a show during a fade-out cancels it (`Fading`). Don't scale or translate the panel's content on show: it made the text shimmer. Views only fade in (`view-in`, opacity only, since the window is resizing at the same time); messages rise in only when they arrive live (`arrive()` marks them), never when a chat is opened whole; a `ResizeObserver` on the chat holds its scroll (end or pinned question) on every frame of AppKit's resize, so the text doesn't slide. No overshooting curves.
- **Quit asks first**: the menu bar's "Quit" shows a native Quit / Cancel alert (`confirm_quit`, `tauri-plugin-dialog`), activating the app first so the alert isn't hidden behind other windows.
- **Model choice**: only the latest alias of each family, at medium or high effort. The last pick is saved by the sidecar in `~/Library/Application Support/QuickClaude/choice.json` (shared by dev and installed copies); without it, the user's Claude Code settings decide.

## Gotchas

- Release builds run `Contents/MacOS/quickclaude-agent`; dev builds run node on the source file. The dev path is compiled in from `CARGO_MANIFEST_DIR`, so rebuild after moving the folder.
- When stopping processes, match exact paths (`/Applications/QuickClaude.app/Contents/MacOS/`, `target/debug/quickclaude$`). Never use broad patterns like `pkill -f vite`; they kill the user's other dev servers.
- Don't drive the UI with simulated keystrokes while the user is at the Mac. A menu bar app never reports as the frontmost process, so focus can't be confirmed, and stray keys land in other apps.
- Claude Code can take over 60 s to start when the Mac is busy (e.g. right after a deploy or login). The spare's start-up timeout is 180 s (`START_TIMEOUT`), and a failed warm-up retries twice quietly before the UI shows "Warm-up failed".
- Starting a new spare process right after an answer briefly slows an immediate next question (about 1.5 s extra for a few seconds).

## Known gaps

- A regular window, not an `NSPanel`; it doesn't appear over full-screen apps.
- No syntax highlighting.
- Tool calls show only a "Using <tool>…" line, not their input or output.
- Hotkey and profile are env vars only (`QUICKCLAUDE_HOTKEY`, `QUICKCLAUDE_PROFILE`, `QUICKCLAUDE_MODEL`), which an app launched from Finder doesn't see.
